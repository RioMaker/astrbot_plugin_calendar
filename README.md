# 历记 · AstrBot 日历插件

维护一本有标记、有备注、可扩展状态的标准日历。目录及插件标识为 `astrbot_plugin_calendar`，初始版本 `0.1.0`。

## 打开日历

需要 **AstrBot 4.29.4 或更新的兼容 4.x 版本**，以及该版本要求的 Python 环境。

1. 将本插件放在 AstrBot 的 `data/plugins/astrbot_plugin_calendar/` 下，安装 `requirements.txt` 中的依赖，并加载插件。
2. 在 **AstrBot WebUI → 插件 → 历记 → 可视化页面 → calendar** 打开日历。较早的界面可能将该入口称为 Pages。
3. 管理员可发送 `/历记` 查看入口说明，或 `/历记 2026-02-17` 查询日期基础信息。指令不会发送私人备注；可在插件常规配置中关闭。

当前版本是一份由已登录 Dashboard 的管理用户共同维护的日历，按实例保存。没有群聊隔离、个人日历或自动发群功能。页面通过 AstrBot 官方 Bridge 访问后台，不另开公网管理端口，也不需要单独设置页面密码。

## 操作方式

| 操作 | 效果 |
| --- | --- |
| 选择红色圆圈「得财」或黑色圆圈「破财」 | 使用默认记号笔；这些是用户自行记录的含义 |
| 新建画笔 | 自定名称、颜色与圆圈／方框／菱形／三角形 |
| 选择画笔后点击日期 | 在日期数字周围绘制一层记号 |
| 再次点击同一日期 | 同一画笔增加一层，最多三层；第四次保持三层 |
| 点击日历标题里的年或月数字 | 对该年或该月独立绘制记号 |
| 再次点击已选画笔，或选择「浏览 / 备注」 | 取消绘画，进入备注模式 |
| 选择橡皮后点击年月日 | 按绘制先后逆序擦除一层，不删除备注或其他状态 |
| 浏览模式点击日期或年月数字 | 打开详情，添加、编辑、删除多条备注及条件状态 |
| 保存备注并关闭详情 | 日历单元格展示彩色缩略条，鼠标悬浮可预览正文 |
| 点击备注条 | 打开对应备注编辑；手机端用点击查看详情 |
| 日历设置 → 扩展字段 | 创建文本、是／否或下拉状态字段 |
| 日期详情 → 放假 / 上班状态 | 手动覆盖安排；选「采用日期库安排」可恢复 |

每条备注可单独设色；默认备注色也可修改。新增、编辑、删除均在后台 SQLite 事务中保存，刷新页面或重载插件后仍保留。备注和条件需要点击各自的保存按钮；关闭时会提醒未保存输入。画笔操作直接保存，页面右侧显示保存状态。

日历始终为**六行七列的标准月历**，相邻月份的补位日期显示为浅色。可以直接跳转年月，选择周一或周日作为一周开始。手机保留同一周历结构，通过日历内部横向滚动查看，不转为列表或卡片流。

## 日期、五行与节假日口径

- 支持选择 `1901–2099` 年。公历日期、星期、农历日期、常见公历／农历节日及二十四节气为计算得到的基础信息。
- 年、月、日分别显示干支；五行明确显示**天干五行、地支本气五行**。例如丙午为「丙·火 / 午·火」，不混用纳音、藏干或时柱。
- 干支年默认在春节换年，可切换为**立春日**换年；月干支按节令日期，日干支按零点。这里是按日查看的日历，不采用交节瞬间或真太阳时排盘。
- 「今天」采用 UTC+8，避免服务器位于其他时区时日期偏移。
- 普通节日与放假调休分开：节日名称不代表该日放假。「休」表示日期库收录的放假日，「班」表示调休上班日，普通周末另行区分。
- 法定节假日安排采用中国大陆数据。首次验证使用 `chinesecalendar 1.12.1`，收录 `2004–2027` 年；页面从实际安装的数据版本读取覆盖范围。
- 超出已收录年份时显示「安排待确认」及提示，不把周末或公历节日推断为法定放假。每年发布新安排后应更新依赖；也可在详情手动补充，并显示「手动设置」。
- 手动追加的节日与基础节日并列保存；不篡改公历日期、干支、农历等基础事实。

## 状态与数据设计

日期键为 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，分别表示年、月、日。三种记录独立存在，不跨年重复，也不将年或月的标记自动复制到每一天。

```text
画笔目录：名称 + 颜色 + 形状
字段目录：名称 + 类型 + 可选状态
每个日期键：
  marks      画笔 ID、层数、实际绘制顺序
  notes      多条备注，每条包含稳定 ID、正文和颜色
  values     扩展字段 ID → 状态值（未设置与「否」不同）
  festivals  手动追加节日（仅日）
  holiday    手动放假调休覆盖（仅日，null 表示采用日期库）
```

修改一支画笔的外观会同步更新其已有标记。已有标记的画笔不能直接删除；已有状态的字段不能直接删除、改变类型或移除旧选项，需先清除对应记录。字段可以更名、增加下拉选项。

边界：最多 32 支画笔、32 个扩展字段；一个年月日数字最多同时使用 4 支画笔，每支 3 层；每个年月日最多 50 条备注，每条 4000 字；每天最多 10 个手动节日。限制同时由后端检查，防止异常请求写入无效数据。

## 持久化、导出与并发

数据保存在 AstrBot 的：

```text
data/plugin_data/astrbot_plugin_calendar/calendar.sqlite3
```

数据目录通过框架 API 获取，不依赖工作目录，也不把记录写进插件源码目录。SQLite 使用事务与 WAL；数据库 schema 版本为 1。遇到比当前插件更新的数据库版本会停止初始化，保留原文件。

「导出记录」下载 JSON，包含画笔、字段、设置和全部年月日记录，不包含可重新计算的日历基础数据。当前版本提供 JSON 导出，尚无页面导入功能。完整迁移可在停止 AstrBot 后备份、恢复整个插件数据目录；不要只复制仍在写入的单个 SQLite 文件。

所有修改携带页面读取时的数据版本，服务端在同一事务里核对。如果另一页面已经更新，本次写入返回冲突，不覆盖较新的记录。输入保留在当前表单中，可在窗口内点击「刷新数据，保留输入」，核对最新记录后再次保存。

快速连续画圈按顺序提交。网络失败后的未完成操作不会自动重放；请刷新核对当前标记再操作，避免重复笔画。后台错误不会把异常详情或备注内容返回给客户端。

## 本地开发与验证

正常的开发环境：

```shell
python -m pip install -r requirements-dev.txt
npm ci
python -m pytest -q
ruff check core main.py scripts tests
ruff format --check core main.py scripts tests
npm run check
npm run test:render
```

浏览器测试使用 Playwright，可设置 `CALENDAR_TEST_BROWSER` 指向测试浏览器；Windows 上自动寻找 Chrome 或 Edge，其他环境可执行 `python -m playwright install chromium`。测试创建独立临时数据库。

无需运行 AstrBot 即可预览本地开发界面：

```shell
python scripts/preview.py --port 8765
```

打开 `http://127.0.0.1:8765`。预览服务仅绑定本机，使用随机凭据，数据在 `.preview/calendar.sqlite3`，与正式插件数据分离。该开发服务不会随插件加载。

验证涵盖日期边界、春节／立春、节日／放假／补班、SQLite 持久化、并发冲突、备注与扩展状态，以及实际浏览器中的绘制、擦除、备注悬浮、跨月、刷新、导出和手机布局。额外模拟 AstrBot 的 `allow-scripts allow-forms allow-downloads` iframe 限制，验证旧版 Bridge 别名、页内确认、保存及下载。AstrBot 接口和 Bridge 宿主仍为本地合约模拟；**不代表真实 AstrBot / QQ 集成或线上验证通过**。

2026-11-11 本地结果：65 项 Python 测试通过（含 10 项真实浏览器场景），3 项 Node 渲染回归测试通过；Ruff、Prettier、JavaScript 语法检查通过。已查看桌面、手机、详情窗口及深色主题截图。测试环境为 Windows、Python 3.10.9、Chrome 157；尚未在 AstrBot 实例的 Python 3.12+ 环境中联调。

## 接口与参考来源

前端使用 `pages/calendar/index.html`，兼容 `AstrBotPluginView` 和 `AstrBotPluginPage` Bridge；后台注册 `/{plugin_name}/month`、`mutate`、`export`。普通 JSON 读写通过 `astrbot.api.web` 返回，访问身份由 AstrBot Dashboard 管理。

- [AstrBot 官方可视化页面与 Bridge 文档](https://docs.astrbot.app/dev/star/guides/plugin-pages.html)（2026-11-11 核对；当前文档推荐 views，并兼容 pages）。
- [lunar-python](https://github.com/6tail/lunar-python)：农历、节日、节气和干支计算，MIT 许可，作为 Python 依赖使用。
- [chinese-calendar](https://github.com/liriansu-opus/chinese-calendar)：放假调休数据，MIT 许可，作为 Python 依赖使用。
- [国务院办公厅关于 2026 年部分节假日安排的通知](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)：核对 2026 春节休假与补班测试样例。

当前仓库尚无远程地址，`metadata.yaml` 的 `repo` 留空。源码及资源可在本地继续维护；没有创建远程、推送或部署。
